# Deep Research Agent

一个**从零手写**（不依赖 LangChain / LangGraph 等框架）的深度研究 Agent：给定一个问题，它会自动规划子问题、搜索网页、阅读并提炼内容，最后生成带引用的研究报告。

> 

## 功能

- **规划**：先把问题拆成 2-4 个子问题，再逐个研究
- **工具调用**：`web_search`（DuckDuckGo 搜索）、`read_page`（抓取网页正文并提炼要点）
- **上下文管理**：网页原文不直接放进对话，先按关注点提炼成要点，控制 token 增长
- **来源管理**：由代码记录读过的网页，参考列表由代码生成，避免模型编造链接
- **停止条件**：限制每个子问题的搜索次数；达到最大步数时强制根据已有信息生成报告
- **可观测性**：记录每一步的 token 消耗和工具调用

## 架构

```
用户问题
   │
   ▼
┌──────────┐

     ▼
┌──────────────────────────────┐
│  Agent loop（最多 N 步）       │
│                              │
│  LLM 决策 ──► 调用工具？        │
│     ▲           │是          │

│                 │否          │
└─────────────────┼────────────┘
                  ▼
        最终报告 + 代码生成的参考来源
```

## 设计决策与取舍

| 问题 | 方案 | 取舍 |
|---|---|---|
| 网页内容太长，每一步都要重发全部历史，token 快速增长 | `read_page` 内先用 LLM 按关注点提炼成 ≤300 字要点 | 每读一页多一次 LLM 调用；可能丢失细节 |
| 模型会引用没读过的来源 | 代码维护已读 URL 列表，模型只标 `[编号]`，参考列表由代码生成 | 搜索摘要不能作为引用依据 |
| 想到哪查到哪，步数多、偏题 | 先规划子问题，并给每个子问题设定搜索预算 | 规划多一次调用；计划不好时会影响结果 |
| 达到最大步数后前面的研究白费 | 到上限时去掉 tools，强制根据已有信息写报告 | 报告可能不完整 |
